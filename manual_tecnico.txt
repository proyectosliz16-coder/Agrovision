
Propósito
El propósito de este manual es servir como guía de referencia para administradores de sistemas, desarrolladores y personal de soporte técnico encargado de la instalación, configuración, operación y mantenimiento de MJ AgroVision.
Asimismo, proporciona la información necesaria para replicar el entorno de ejecución del sistema, realizar su despliegue de manera correcta y comprender las dependencias, configuraciones y restricciones requeridas para garantizar su funcionamiento adecuado. Este documento también facilita futuras tareas de actualización, corrección de errores y escalabilidad del proyecto.

Backend

Este proyecto fue desarrollado utilizando una arquitectura basada en tecnologías web modernas e inteligencia artificial para el procesamiento y análisis de imágenes agrícolas. 

Para asegurar la reproducibilidad del entorno de desarrollo y producción, el sistema MJ Agrovision fue construido utilizando las siguientes versiones de frameworks y librerías:

A continuación, se describen los principales frameworks y estándares empleados durante el desarrollo.
React
React es una biblioteca de JavaScript desarrollada por Meta para la construcción de interfaces de usuario dinámicas e interactivas. Su enfoque basado en componentes permite desarrollar aplicaciones web escalables y reutilizabl  es.
Dentro de MJ AgroVision, React se utiliza para construir la interfaz gráfica del usuario, permitiendo la carga de imágenes, la visualización de resultados y la interacción con las funcionalidades del sistema de análisis agrícola.

Vite
Vite es una herramienta de construcción y desarrollo para aplicaciones web modernas. Su principal característica es la rapidez en el proceso de compilación y actualización durante el desarrollo. 
En MJ AgroVision, Vite es utilizado para gestionar el entorno de desarrollo del frontend, optimizando la construcción de la aplicación y permitiendo una experiencia de desarrollo más eficiente.

FastAPI
FastAPI es un framework para el desarrollo de APIs web utilizando Python. Está diseñado para ofrecer alto rendimiento, facilidad de desarrollo y generación automática de documentación.
Dentro del sistema, FastAPI se encarga de gestionar las solicitudes enviadas desde la interfaz web, procesar las imágenes recibidas y devolver los resultados generados por el modelo de inteligencia artificial. 

Uvicorn
Uvicorn es un servidor ASGI de alto rendimiento utilizado para ejecutar aplicaciones desarrolladas con FastAPI.
Su función dentro de MJ AgroVision es proporcionar el entorno de ejecución del backend, permitiendo la comunicación entre el cliente web y los servicios de procesamiento de imágenes. 

PyTorch
PyTorch es una biblioteca de aprendizaje profundo ampliamente utilizada para el desarrollo y entrenamiento de modelos de inteligencia artificial.
En MJ AgroVision se utiliza para cargar y ejecutar el modelo de segmentación entrenado, permitiendo identificar automáticamente las region  es correspondientes a frijol, maleza y suelo dentro de las imágenes analizadas.

Segmentation Models PyTorch
Segmentation Models PyTorch es una biblioteca especializada en tareas de segmentación semántica de imágenes. 
Esta herramienta facilita la implementación de arquitecturas avanzadas de visión por computadora, utilizadas en el desarrollo del modelo U-Net empleado por MJ AgroVision.

Albumentations
Albumentations es una biblioteca orientada al procesamiento y aumento de imágenes para aplicaciones de visión artificial.
Durante el desarrollo del modelo de inteligencia  artificial se utilizó para realizar transformaciones y preprocesamiento de imágenes, contribuyendo a mejorar la capacidad de generalización del modelo.

OpenCV
OpenCV es una biblioteca de visión por computadora utilizada para el procesamiento de imágenes. 
En MJ AgroVision se emplea para la lectura, manipulación y preparación de imágenes antes y después de ser procesadas por el modelo de inteligencia artificial.

Restricciones del producto
Permisos de ejecución del producto
Para el correcto funcionamiento del sistema es necesario que el usuario o cuenta de servicio que ejecute el backend tenga permisos de lectura sobre el archivo del modelo de inteligencia artificial unet_frijol.pth, así como permisos de lectura y escritura en los directorios temporales utilizados durante el procesamiento de imágenes.

Las políticas de uso para cada usuario
El sistema está diseñado para ser utilizado por usuarios que requieran realizar análisis de imágenes agrícolas mediante inteligencia artificial.
Las imágenes cargadas al sistema deben cumplir con los formatos soportados por la plataforma:
•	JPG (.jpg, .jpeg)
•	PNG (.png)
•	TIFF(.tiff)
Cada solicitud de análisis es procesada de forma individual con el objetivo de garantizar la estabilidad del sistema y evitar la saturación de los recursos disponibles.

Restricciones de recursos
El procesamiento de imágenes mediante el modelo de segmentación U-Net requiere una cantidad considerable de recursos computacionales, principalmente de CPU y memoria RAM.
Cuando se ejecutan múltiples análisis simultáneamente en equipos con recursos limitados, el rendimiento general del sistema puede verse afectado, incrementando los tiempos de respuesta y procesamiento.

Restricciones de tiempo
El tiempo necesario para completar un análisis depende de diversos factores, entre los que se encuentran:
•	Resolución de la imagen cargada.
•	Tamaño del archivo procesado.
•	Capacidad de procesamiento del servidor.
•	Cantidad de solicitudes concurrentes.
Por lo tanto, el tiempo de respuesta de la API puede variar dependiendo de las condiciones de ejecución del sistema.

Restricciones de alcance
AgroVision MJ fue desarrollado exclusivamente para la segmentación semántica de imágenes agrícolas relacionadas con cultivos de frijol.
El modelo de inteligencia artificial ha sido entrenado para identificar las siguientes clases:
•	Frijol.
•	Maleza.
•	Suelo.
•	Fondo negro (principalmente en ortomosaicos)
El sistema no garantiza resultados precisos cuando se utilizan imágenes de otros cultivos, escenarios diferentes a los considerados durante el entrenamiento o fotografías con condiciones adversas de iluminación, desenfoque o baja resolución.

Restricciones de calidad
La calidad de los resultados generados por el sistema depende directamente de la calidad de las imágenes proporcionadas por el usuario.
Factores como iluminación insuficiente, sombras excesivas, desenfoque, baja resolución o presencia de elementos no contemplados durante el entrenamiento del modelo pueden afectar la precisión de la segmentación realizada por la inteligencia artificial.

Paso a paso para la instalación y configuración del servidor de base de datos
MJ Agrovision fue diseñado bajo un enfoque de procesamiento "en caliente" (On-the-fly) y sin estado (Stateless) por razones de privacidad y eficiencia. Dado que las imágenes de ortomosaicos aéreos suelen pesar varios megabytes, almacenar cientos de imágenes y sus resultados saturaría rápidamente el almacenamiento en la nube. Por lo tanto, el sistema recibe la imagen en la memoria RAM del servidor, procesa los tensores con PyTorch, devuelve el resultado encapsulado en JSON/Base64 directamente al navegador del cliente y finalmente purga la memoria. El resultado final se persiste en un documento PDF que se descarga exclusivamente en el equipo local del usuario, garantizando privacidad total.

Las solicitudes de análisis son enviadas desde la aplicación web al servidor backend, donde son procesadas por el modelo de inteligencia artificial. Posteriormente, los resultados obtenidos son enviados nuevamente a la interfaz para su visualización por parte del usuario.
Despliegue del producto
MJ AgroVision es una aplicación web que se encuentra alojada en un servidor y puede ser accedida mediante un navegador web compatible. Debido a su naturaleza web, no requiere la instalación de componentes adicionales en el equipo cliente.
Para acceder al sistema, el usuario deberá ingresar a la dirección electrónica asignada al servidor:
Visitar en el navegador http://localhost:3000/.
•	Respuesta esperada: Se visualiza la pantalla principal con el logotipo de MJ Agrovision.
•	Prueba de Inferencia Completa (End-to-End) Dentro de la aplicación, el administrador sube una imagen estandarizada de prueba.
•	Respuesta esperada: El servidor procesa la imagen sin arrojar alertas (Timeout o Memory Error). El frontend recibe y pinta la máscara (Azul/Verde/Café,Negro), confirmando que el peso numérico de los tensores fue resuelto correctamente y los gráficos se actualizan.
